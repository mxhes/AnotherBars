# Fading Implementation Plan (Plan 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each Blizzard bar gets a Fading section on its Edit Mode panel:
- "Opacity out of combat" (0-100%).
- "Full on mouse-over".

The bar shows fully in combat, while the mouse is over it, and while Edit Mode is open. Otherwise it fades to the chosen opacity.

**Architecture:**
- **The rule** (`Core/Fade.lua`, pure, tested with `h.load`): `Fade.target` decides the bar's alpha from settings and state, and `Fade.step` moves the alpha toward it over time.
- **The driver** (`Skin/Fade.lua`, client, one per bar):
  - It keeps the state: combat from `PLAYER_REGEN_DISABLED` / `_ENABLED`, mouse-over by polling `IsMouseOver` at 10 Hz, Edit Mode from LibEditMode's `enter` / `exit` callbacks.
  - It animates the bar frame's alpha on its own `OnUpdate`.
- **Inherited alpha:** our overlays, glow and the padding-0 bar frame are children of the bar or its buttons, so they fade with it.

**Tech Stack:** Lua 5.1, WoW Forever client API (Interface 16001), plain-Lua tests, luacheck.

**Spec:** `docs/superpowers/specs/2026-11-26-anotherbars-design.md`, sections "Fading" and the Edit Mode sections ("Fading: opacity out of combat, full opacity on mouse-over"). The Plan 1 spike confirmed that `SetAlpha` on a bar frame in combat works, with no taint (`docs/CHECKLIST.md`, "Plan 1 spike").

## Global Constraints

- Lua 5.1, `## Interface: 16001`. Each new `.lua` file goes in the `.toc` and the layout table of `docs/DEVELOPMENT.md`.
- **Taint:**
  - Only `SetAlpha` on the bar frame. No fields on Blizzard frames.
  - Never use Blizzard's fade helpers: `UIFrameFadeIn` / `UIFrameFadeOut` write `fadeInfo` onto the frame.
  - All state lives in our own tables; our driver frame is our own.
- `SetAlpha` on the bar frame runs in combat as well (spike), so fading does not wait for combat to end. It touches nothing else of the bar.
- **New settings:** each needs a default in `Common.defaults`, a label of at most 24 characters and a tooltip. Texts go through `ns.L`, with German in `Locales/deDE.lua`.
- **Client checks:** every client name not yet confirmed gets `UNVERIFIED (check in client)` and a line in `docs/CHECKLIST.md`.
- No new art.

## Calls made in this plan (the player may overrule)

- **Defaults:** "Opacity out of combat" 100% (no fading until the player lowers it); "Full on mouse-over" on.
- **At 100%** the driver never touches the bar's alpha. It doesn't poll or call `SetAlpha`, so another addon or Blizzard can keep its own alpha.
- **In combat** the bar is always full. This isn't a setting: the spec says full in combat.
- **While Edit Mode is open** every bar is full, so you can see what you place.
- **Fade speed:** 0.2 s to full and 0.5 s to faded. There is no setting.
- **Mouse-over counts** the bar frame and every shown button. At padding 2 the gaps between buttons are part of the bar frame, so moving across them doesn't blink.
- **A bar turned off** in Settings gets no driver, and its alpha stays Blizzard's.

## Review Focus

1. **Opacity set back to 100% after fading:** the bar returns to alpha 1 once, then the driver stops touching it. Test in Task 2.
2. **Entering combat mid-fade:** the bar goes to full, from the alpha it has, without waiting for the fade to end. Test in Task 2.
3. **Mouse leaves one button and enters the next across the gap:** no fade-out starts as long as the mouse is over the bar frame. Test in Task 2.
4. **Edit Mode opened while faded, then closed:** full while open, faded again after. Test in Task 2.
5. **LibEditMode missing** (no `Libs/`): fading works, and the Edit Mode rule is simply off. Test in Task 2.

### Task 1: Settings and the pure rule (`Core/Fade.lua`)

**Files:**
- Create: `AnotherBars/Core/Fade.lua` (in the `.toc` after `Core/Look.lua`), `tests/test_fade.lua`
- Modify: `AnotherBars/Bars/Common.lua` (settings and defaults only), `AnotherBars/Locales/deDE.lua`, `tests/test_barmodules.lua`

**Interfaces:**
- Produces:
  - **Defaults:** `Common.defaults` gains `fadeAlpha = 100` and `fadeMouseover = true`.
  - **A third section after Text:**
    - `{ section = "Fading", controls = { ... } }` holds:
    - `{ key = "fadeAlpha", type = "slider", label = "Opacity out of combat", min = 0, max = 100, step = 5, tooltip = "How visible the bar is out of combat; 100 never fades" }`
    - `{ key = "fadeMouseover", type = "checkbox", label = "Full on mouse-over", tooltip = "Shows the bar fully while the mouse is over it" }`
  - **`Fade.active(fadeAlpha) -> bool`:** true when `fadeAlpha < 100`.
  - **`Fade.target(opts, st) -> number`:**
    - `opts = { fadeAlpha, fadeMouseover }` and `st = { combat, editMode, mouse }` (booleans).
    - Returns 1 when `combat`, `editMode`, or `mouse and fadeMouseover`; else `fadeAlpha / 100`, clamped to 0..1.
  - **`Fade.step(current, target, dt) -> number`:**
    - Moves `current` toward `target` at `1 / Fade.IN` per second when rising and `1 / Fade.OUT` when falling, without overshooting.
    - `Fade.IN = 0.2`, `Fade.OUT = 0.5`.

### Task 2: The fade driver (`Skin/Fade.lua`) and wiring

**Files:**
- Create: `AnotherBars/Skin/Fade.lua` (in the `.toc` after `Skin/BarFrame.lua`), `tests/test_skin_fade.lua`
- Modify: `AnotherBars/Bars/Common.lua`, `AnotherBars/EditMode/System.lua` (Edit Mode enter / exit), `.luacheckrc` if needed

**Interfaces:**
- Consumes: `Fade.target`, `Fade.step`, `Fade.active`, `Bars.get`, `Options.get`, `Common.buttons(id)`, `EditMode.System.lib()`.
- Produces:
  - **`SkinFade.apply(barId, opts)`:** `ns.Skin.Fade`, called `SkinFade` here. `opts = { fadeAlpha, fadeMouseover }`.
    - On the first call it creates one hidden driver frame of ours for the bar and stores the opts.
    - **When `Fade.active`:** it shows the driver. The driver's `OnUpdate(elapsed)` does three things:
      - Re-reads the mouse every 0.1 s: `frame:IsMouseOver()` for the bar frame, or any shown button's.
      - Computes `Fade.target`.
      - Sets the bar frame's alpha to `Fade.step(current, target, elapsed)`. `SetAlpha` is called only when the value changed.
    - **When not active:** if we had changed the alpha, it sets it back to 1 once, then hides the driver (no `OnUpdate`).
  - **`SkinFade.setCombat(on)`** and **`SkinFade.setEditMode(on)`:** shared state for every bar's driver. Combat follows one event frame (`PLAYER_REGEN_DISABLED` → true, `PLAYER_REGEN_ENABLED` → false). At start the state is `InCombatLockdown()`.
  - **`SkinFade.state(barId)`:** `{ frame, alpha, opts }` for tests.
  - **`EditMode/System.attachAll`** registers LibEditMode's `enter` / `exit` callbacks once: `lem:RegisterCallback("enter", ...)` / `("exit", ...)`, which call `SkinFade.setEditMode(true / false)`. UNVERIFIED on Forever, which is why it gets a CHECKLIST line.
  - **`Common`:**
    - `Common.fadeOpts(id)` → `{ fadeAlpha, fadeMouseover }`.
    - `SkinFade.apply(id, Common.fadeOpts(id))` runs on create and on apply. It runs outside `Combat.after`: alpha is allowed in combat.
